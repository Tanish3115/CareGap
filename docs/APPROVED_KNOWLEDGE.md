# Offline medication pair evidence

The medication comparison API now has an executable offline evidence adapter in `approved_knowledge.py`. The original provider interface remains available for separately approved integrations. No licensed drug database, drug-equivalence inference, dose calculator or live interaction service is bundled or enabled.

Set `KNOWLEDGE_MODE=approved_catalog` only with an approved private catalog, its exact SHA-256, `KNOWLEDGE_CATALOG_APPROVED=true` and `KNOWLEDGE_APPROVAL_REFERENCE`. Configure the matching approved terminology release as documented in MEDICATION_TERMINOLOGY.md. Mount both private files read-only; do not place licensed or clinical data under application source directories. The default is disabled. The disposable hosted demo forces it disabled regardless of inherited settings.

The strict catalog schema is `caregap-pair-evidence-v1`. Required fields include reference, release, license reference, clinical review reference, UTC issue/expiry dates and the exact terminology-catalog SHA-256. `pairs` contains distinct left/right `(system, code)` identities, a finding of `advisory` or `no_listed_alert`, a message and an evidence reference. Duplicate or reversed duplicate rules are rejected. Catalog files are bounded to 5 MiB/20,000 rules. Missing approval, changed bytes, invalid schemas, mismatched terminology releases and expired/future releases fail closed without exposing paths or data in errors. Operator references record approval evidence; their presence is not independent certification by this application.

Only explicitly reviewed, unambiguous, approved terminology mappings from current clinician-confirmed source revisions are eligible. A later transcription review or prescription draft excludes the older mapping from this adapter. Manually entered medication names and patient medication-use reports are not silently mapped. At most the first 100 recorded evidence entries are considered; every excluded entry is counted. Repeated coded identities are grouped without merging the underlying records.

Results report assessed and unassessed distinct-code pairs, eligible/excluded source counts, pinned provider release/hash, evidence references and source IDs. Missing pair rules are **unassessed**, not negative findings. Findings are capped at 250 with an explicit truncation flag. The dashboard displays the release, coverage and source evidence, and removes old findings when a release becomes unavailable.

These are matches across recorded historical sources. They do not establish current simultaneous use. Allergies, cross-reactivity, safe doses, clinical correctness and treatment choices remain unevaluated. `clinical_safety_checked` remains false; a catalog entry saying `no_listed_alert` is scoped evidence rather than a whole-regimen safety clearance. Nothing changes orders or medication use.

Tests exercise exact reviewed mappings, forged/unreviewed/synthetic mappings, missing coverage, duplicate rules, approval/release/hash/expiry failures, current-source staleness, authorized API integration and the translated partial-coverage/unavailable UI. All test catalogs contain explicitly synthetic software fixtures, not clinical evidence.
