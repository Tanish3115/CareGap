# Implementation roadmap

Updated 2 November 2026. The local application now includes structured clinical/care records, medication event comparison, interventions, mock coordination, source-linked overviews, a FHIR subset, synthetic risk evaluation and organization-bound sharing. This is substantial local functionality, not completion of every advanced/production requirement. No GitHub push is authorized. See [PROGRESS.md](PROGRESS.md) and [DEPLOYMENT_GATES.md](DEPLOYMENT_GATES.md).

## Next dependency-ordered tasks

1. Review the source-bound clinical/extraction/normalization workflows with an appropriate clinician and supply an approved licensed terminology/knowledge release before real clinical use.
2. Obtain native-language medical review and expand FHIR mappings against the approved receiving system's conformance tests. Clinical group scopes and the combined current-record timeline are implemented; see CONSENT_SCOPES.md.
3. Configure approved providers only after privacy/consent/institutional review; no external messages or patient-data model calls are configured now.
4. Collect representative approved outcomes before developing clinical predictors or causal policies; synthetic demonstrations remain separate.
5. Complete independent deployment/security/accessibility/performance/retention review and managed infrastructure before real patient deployment.

Every milestone must preserve a working application and add meaningful tests. Passing software checks does not establish clinical validity, production certification or legal compliance.

See MASTER_PROMPT_CHECKLIST.md for every original specification section, explicit optional/local-fallback decisions and concrete source/test evidence. QUALITY_CHECKS.md records the maintained tooling and repeatable accessibility/load checks.
