# Durable local document processing

The processing slice uses the existing SQL database as a durable queue and local Tesseract/Poppler for OCR. It reads source text and supports attributed transcription review; it is not a medication extractor or clinical verifier.

Uploads enqueue a job in the same transaction as document metadata and the upload audit event. A separate `python -m app.worker` process claims jobs using an atomic conditional update. Five-minute leases recover work after a worker stops; a random lease token prevents an older worker from overwriting a newer attempt. Attempts are bounded at three. Failed jobs can be retried explicitly by the patient owner, and last-attempt crashes become visible terminal failures. Owners can update a completed `source-text-v1` result to `source-ocr-v2` within the attempt limit. Two workers cannot claim the same live lease.

Each parser runs in a supervised subprocess with a 150-second timeout and a 768 MiB address-space limit on Linux. The original SHA-256 is verified before reading. Text is bounded to 100,000 characters and PDFs to 200 pages. Up to five scanned pages are OCR'd by default (`OCR_MAX_PAGES`); further scans are explicitly flagged. Poppler rendering is bounded to 2200px and eight seconds per page; Tesseract receives images at most 2400px wide/high and has a twelve-second limit. English printed text is the initial target. Per-page methods, word boxes/confidence, unreadable pages, missing tools and limits remain visible. Engine confidence is not clinical certainty. Parser details/source text are excluded from logs, and the parent owns the subprocess's temporary workspace.

Results contain original-source checksum, processor version, page count, OCR/truncation flags and explicitly unverified text. They never create trusted diagnoses, medicines, notes or prescriptions. Source files and document verification status remain unchanged. The dashboard's **Show processing** panel polls queued/running jobs and displays terminal results or an owner-only retry action. Older documents are processed only when their owner explicitly requests it.

Processing reads/results use the same document-level consent rules as downloads, including selected records, categories, professional verification, expiration and revocation. Operational administrators cannot inspect results. Only the patient owner can request/retry processing. Audit events contain operational metadata, not copied source text.

`PrivateObjectStore.materialize` separates verified source access from consumers. Both private local storage and an actual S3-compatible SDK adapter are implemented. `medical_documents.storage_backend` routes each document independently; migration `0008` marks existing records local. Remote sources are downloaded into private temporary files, bounded/checksummed before serving or processing, and cleaned afterward. The API never returns direct object URLs. The worker's local vault mount remains read-only. Managed encryption and independent production review remain open.

Source reviews are append-only revisions with original generated text, reviewed text, source checksum, processor/job/attempt identity, author and reason. Saving requires explicit original-source/patient/date confirmation, a matching completed processing attempt, the current review version and an intact source. Job/document compare-and-set locks protect reprocessing and concurrent review edits. Patients can review their own source; doctors also need document access and explicit clinical read/write consent. Document-only grants do not expand to human-added review text. Patient-reviewed and clinician-reviewed transcriptions are distinct; document verification and medication/diagnosis records are not changed.

## Optional private object storage

Local files remain the default. Run `scripts/configure.py` to generate missing local MinIO credentials (existing secrets are preserved), then `docker compose --profile object-storage up --build -d minio`. The MinIO service binds only to `127.0.0.1:59000` by default and keeps its console private. It is built from the official pinned source release because public prebuilt images were unavailable; see [implementation references](OCR_STORAGE_PLAN.md).

Configure `STORAGE_BACKEND=s3`, `S3_ENDPOINT_URL`, `S3_BUCKET`, `S3_REGION`, `S3_ACCESS_KEY_ID` and `S3_SECRET_ACCESS_KEY` in ignored configuration. Docker uses `http://minio:9000`; host development uses `http://127.0.0.1:59000`. Use a private bucket and dedicated application credentials limited to required object read/write/delete permissions. Keep root/administrative credentials for provisioning/testing; do not use them as production app credentials. Provision the bucket explicitly with `python -m app.storage_admin` inside the configured backend, or `python scripts/provision_bucket.py` on the host. Provisioning does not grant anonymous access or change an existing bucket's permissions. Production custom endpoints require HTTPS and normal certificate verification.

`scripts/check_s3.py` uses local MinIO administrative credentials only to create a uniquely named synthetic test bucket, run real upload/download/processing/integrity/anonymous-denial checks, and remove that bucket. It never uses the application bucket or migrates existing files.

Run locally with `docker compose up --build -d`; Compose starts the API, frontend, database and worker. Without Docker, run migrations and the API normally, then from `backend` run `.venv/Scripts/python.exe -m app.worker` in a separate terminal. `--once` processes at most one eligible job. `--poll-seconds` controls idle polling. The API must apply migrations before a worker starts.

Acceptance: actual text PDFs, printed images and scanned PDFs produce source-grounded unverified text; unreadable/blank pages and unavailable tools remain explicit. Tampered sources fail; retries respect their limit; expired leases recover; stale workers cannot overwrite results; concurrent claims are exclusive; unauthorized and revoked readers are denied. Browser tests cover a real isolated worker, editable review/history and the original-source boundary. Actual MinIO and Linux OCR tests cover the external storage and OCR paths separately.
