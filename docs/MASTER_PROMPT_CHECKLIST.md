# Master-prompt implementation traceability

Reviewed 2 November 2026 against the complete [original specification](MASTER_PROMPT.md), preserved verbatim. User steering narrows languages to Kannada, Telugu, Tamil, Malayalam, English and Hindi; selects configurable integrations/local test modes; permits patient-owned consultation deletion; and prohibits pushing. These instructions supersede older alternatives in the specification.

**Local** means implemented software with local/synthetic verification. **Bounded** means the implemented fallback or limited mapping explicitly described below; it does not claim an unavailable clinical service. **External** means access, data, infrastructure or independent approval that code cannot supply. **Optional** means acknowledged and deliberately inactive. This checklist does not turn those statuses into a production-completion percentage.

## Deliberate architecture equivalents

The subsequent deletion request is implemented for uploaded documents, consultations, individual follow-ups, medication-use reports and structured health/care records. Ownership, current versions, historical source dependencies and care/intervention links are checked. Migration `0019` adds transactional private-file cleanup with retry/status receipts; the OCR worker keeps its read-only mount. Original imports, backups and audit metadata retain their documented scope. See RECORD_DELETION.md and the API/browser deletion tests. This adds deletion functionality without claiming external clinical/provider/deployment requirements have been satisfied.

- Typed shared components and same-origin fetch are used instead of introducing shadcn/TanStack solely to match a recommended brand list. Clinical data is not persisted in browser caches; workspaces refresh/remount when permissions change. TypeScript, accessible controls and tested loading/error states remain enforced.
- The transactional SQL queue is the permitted reliable-worker equivalent to Celery. Leases, retries, crash recovery and processing states are tested; Redis provides shared throttling rather than a second uncoordinated queue.
- Models train only on explicitly artificial data. Optional research packages are isolated and hash-locked. No representative data or clinical/causal effectiveness is fabricated to make the checklist appear complete.
- The source prompt is preserved so optional/conditional requirements are not silently relabeled as completed live integrations. The checklist covers all 22 sections, including original startup tasks and execution/quality rules. Real-world approval gates remain open even when every local software check passes.
